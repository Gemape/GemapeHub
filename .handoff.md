## Regras que não podem ser quebradas

- **Supabase real:** nada é criado, alterado ou apagado (tabelas, migrations, políticas, gatilhos, usuários) sem ordem explícita do responsável. Estamos na **Fase 1**: tudo roda em modo demonstração (`VITE_DEMO_MODE` diferente de `"false"`), com dados fictícios no navegador. Se uma tarefa exigir tabela, migration ou auth, **pare e avise o responsável**.
- **Git:**
  - Nunca faça commit direto na `main`, que sincroniza com o Lovable. Nunca reescreva histórico publicado nem faça force-push.
  - Use uma branch por tarefa: `fix/`, `feat/`, `docs/` ou `test/`.
  - Os commits são pequenos, com mensagem em português.
  - Rode `git pull origin main` antes de abrir o PR.
  - Nunca faça merge do próprio PR. O merge é do responsável.
- **Todo PR tem:**
  - título e resumo;
  - resultado dos testes por módulo;
  - screenshots;
  - link do preview da Vercel (`https://gemapehub-git-<branch-com-hifens>-gemape.vercel.app`);
  - passo a passo para testar no preview.
- **Depois de cada push:** passe o link do preview e peça ao responsável para atualizar a produção (https://gemapehub.vercel.app/), o que só acontece quando ele faz o merge na `main`.
- **Depois de cada merge:** confira o status do deploy do commit na `main` e comente no PR os links de produção e de preview.
- **Campos e divergências:**
  - Campo extra além do MD só entra com aprovação prévia, proposta no PR antes de implementar.
  - Se houver contradição entre o MD e `docs/decisoes-especiais.md` ou o histórico, **pare e pergunte**.
  - Toda mudança de MD é registrada como decisão aprovada em `docs/decisoes-especiais.md`.
- **Idioma:** o responsável escreve em português. Responda em português, curto, sem colar saída bruta de ferramentas. Quando ele pedir "rode o code review", entregue um resumo próprio em português e corrija os achados.
- **Credenciais:** nunca coloque credenciais reais no repositório.

## Decisões técnicas e arquitetura

- **Stack:** React, TypeScript, TanStack Start, Router e Query, e Supabase. O build detecta a Vercel pela variável `VERCEL` (`vite.config.ts`). Fora da Vercel, o build gera o servidor Node (`npm start`).
- **Modo demonstração:**
  - `src/integrations/supabase/demo-client.ts` simula o Supabase com os dados na chave `gemape-demo-dados` do localStorage.
  - Não emula joins nem gatilhos, e `.or()` e `.not()` não fazem nada.
  - Campos que ainda não existem no banco real só são enviados quando `import.meta.env["VITE_DEMO_MODE"] !== "false"`. Um exemplo é o e-mail do empregado. Cada um desses campos fica listado em `docs/pendencias-fase2.md`.
- **Cadastros > Gerais:**
  - Os dados ficam em `src/lib/parametros-base.ts`, na chave `gemape-demo-parametros-base` do localStorage. O hook é `useParametrosBase()`, e `executar()` mostra o toast.
  - Os ids de categoria são `cat-epi`, `cat-uniformes`, `cat-ferramentas` e `cat-veiculos`.
  - `proximoCodigo(regra, existentes)` gera o código SIGLA-0001 a partir do maior existente + 1.
  - Nenhum módulo mantém lista própria: tudo vem de Cadastros > Gerais.
- **Clique duplo:** o salvamento é travado com `useRef` (`salvando`). A trava continua depois do sucesso, até o diálogo reabrir, e é liberada em `onError`.
- **Empregados (`src/lib/empregados.ts`):**
  - `hojeLocal()` devolve a data local no formato AAAA-MM-DD. Não use `toISOString()`, que dá a data em UTC.
  - `demissaoVencida` considera a demissão vencida a partir do próprio dia.
  - `empregadoAtivo(e)` exige `ativo` e demissão não vencida.
  - `prepararEmpregado` valida e mantém CPF e matrícula antigos quando não mudaram.
  - `bloqueioPorDemissao(e, operacao, dataMov)` só libera a operação `"encerramento"`. Ele usa a data mais tarde entre hoje e a data da movimentação.
  - `useEmpregados(empresa, true)` filtra por `empregadoAtivo`. Para nomes e históricos, use a lista completa (`useEmpregados(empresa)`).
- **Ficha de EPI:** `src/lib/fichas-epi.ts`, chave `gemape-demo-fichas-epi`. Tem uma trava de integridade: se os dados salvos não puderem ser lidos, ela não grava por cima.
- **Fornecedores:** `src/lib/fornecedores-demo.ts`. O campo `categorias: string[]` guarda ids de Cadastros > Gerais. As `naturezas` antigas são convertidas na leitura.
- **Veículos:** `src/lib/veiculos.ts` (`normalizarPlaca`, `placaValida`, `formatarPlaca`, `anoValido`, `placaRepetida`).
- **HTML dos termos:** use `escaparHtml` de `src/lib/gemape.ts` ao montar o HTML.
- **Perfis de acesso:** Administrador, RH e Padrão. O Padrão só lê. Devolução e exclusão de cadastro são só do Administrador. A implementação fica para o fim, junto com a auth e o banco (Fase 2).

## Comandos e testes

```bash
npm install
npm run typecheck        # TypeScript sem erros
npm test                 # node --experimental-strip-types --test tests/*.test.mjs (rodar na raiz)
npm run build            # build de produção; build quebrado = deploy quebrado na Vercel
npm run dev              # modo demonstração; na tela de login use "Acessar demonstração"
```

- Formate com `npx prettier --write` só os arquivos novos ou alterados. Alguns arquivos antigos não seguem o Prettier, e reformatá-los polui o diff.
- Status do deploy de um commit: `curl -s https://api.github.com/repos/Gemape/GemapeHub/commits/<sha>/status | jq .state`.
- As screenshots dos PRs ficam na branch órfã `screenshots` e são referenciadas como `https://github.com/Gemape/GemapeHub/blob/screenshots/<pasta>/<arquivo>.png?raw=true`.
